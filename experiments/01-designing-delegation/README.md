# Experiment 01 — Designing delegation

## Context

> "I need to organize a user interview with a client next week."

This first exploration starts with an everyday coordination task. The request names a goal but leaves much unstated: what “organize” includes, which details matter, and who makes the decisions. I'm interested in how that ambiguity changes the experience when an AI agent acts on the user's behalf.

**What should the user delegate, what should the agent decide, and where should control return to the user?**

## From interaction to delegation

`User → Interface → Action`

`User → Intent → Agent → Actions → Outcome`

I’m using these two sketches to explore a shift in the user's role: from carrying out interface actions to expressing an intent that an agent interprets and acts on. The design question extends beyond the actions themselves to how the user and agent establish and maintain a shared understanding of the goal. These are starting points for exploration, not a formal model.

## Design questions

- What does the user mean to delegate by asking the agent to “organize” the interview, and how might the agent interpret that scope differently?
- Which decisions might the user expect the agent to make independently, and which would they expect to retain?
- What assumptions might the agent make about the client, timing, or interview, and how could the user recognize and correct them?
- Where might confirmation help establish shared understanding, and where might it interrupt the delegation?
- How could the user change direction or take over, particularly if the agent misunderstands the request or cannot complete it?
